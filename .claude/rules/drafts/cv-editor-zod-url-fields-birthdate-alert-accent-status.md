## Luật 1 (STRICT) — Field kiểu URL trong block editor tự-quản-state (KHÔNG react-hook-form): validate bằng zod `z.union([z.literal(""), z.string().trim().url()])`, hiện lỗi khi BLUR (không mỗi keystroke)
- Repo có 2 style validate URL: (a) **react-hook-form + zodResolver** (form thật, submit-based — vd `usePinExternalProjectForm`: `z.union([z.literal(""), z.string().trim().url().max(N)])`); (b) **state tự quản + regex tay** (vd `useEditSubmissionForm.validateUrl` — GitHub/Google Docs URL theo `SubmissionType`, không dùng zod, lỗi hiện khi `touched`).
- **CV block editor KHÔNG dùng RHF** (blocks là JSON tự do `Record<string,unknown>`, mutate trực tiếp qua `onChange({...block, items})`) → validate URL field ở đây dùng **zod TRỰC TIẾP (không qua RHF)**: 1 helper dùng chung `isValidOptionalUrl(value) = z.union([z.literal(""), z.string().trim().url()]).safeParse(value.trim()).success` (file `CV/urlValidation.ts`), gọi trong component để tính `isInvalid`.
- **Touched state tự quản (`useState<Set<...>>`)** — field ĐƠN (Personal, 1 item) key theo tên field; field LẶP (Certification, N item) key theo `item.id`. Lỗi CHỈ hiện khi `touched && !isValidOptionalUrl(value)` (không hiện khi rỗng/chưa blur) — mirror `SubmissionRow`/`useEditSubmissionForm` (blur-triggered, không chặn gõ).
- **Hiển thị lỗi = `TextField isInvalid` + `<FieldError>{t("cv.blocks.common.invalidUrl")}</FieldError>`** (HeroUI, đúng [[heroui-textfield-helper-error-needs-slot]] — slot `errorMessage` tự động qua `FieldError`). KHÔNG chặn submit/autosave — chỉ hiện trạng thái lỗi thị giác (CV vẫn tự lưu, người dùng tự sửa).
- **Placeholder field URL phải là URL HỢP LỆ mẫu (có scheme `https://`)** — không để placeholder dạng bare-domain ("linkedin.com/in/ban") khi field validate bằng `z.string().url()` (url() đòi scheme) → user gõ đúng-như-placeholder vẫn báo lỗi = mâu thuẫn. Sửa placeholder LinkedIn/credentialUrl → `https://linkedin.com/in/…` / `https://credly.com/badges/…`.
- **Field nào là URL thật (validate) vs field-tưởng-là-URL (không validate):** `linkedinUrl` (Personal), `credentialUrl` (Certification mới thêm) → validate. `githubUsername` = USERNAME (không phải URL) → KHÔNG validate url(). Trước khi thêm zod validate 1 field, xác nhận nó THẬT SỰ chứa URL tuyệt đối, không phải slug/username.

## Luật 1b (STRICT) — Field NGÀY = HeroUI `DatePicker`, `variant="secondary"` đặt trên `DateField.Group` (KHÔNG quên → field trắng lệch sibling)
- Field kiểu NGÀY (ngày sinh, ngày cấp…) = HeroUI **`DatePicker`** (segmented `DateField` + `Calendar` popover), KHÔNG `<Input>` text thô. Value lưu ISO string (`@internationalized/date` `parseDate(str)` ↔ `date.toString()`); `maxValue={today(getLocalTimeZone())}` cho ngày-sinh (không cho tương lai).
- **Variant `secondary` của DatePicker nằm trên `<DateField.Group variant="secondary">`, KHÔNG trên `<DatePicker>` root** (khác `TextField` — ở đó variant trên `<TextField>`). Quên → DateField.Group mặc định `primary` (nền `bg-field` TRẮNG + shadow) → lệch hẳn các sibling TextField `secondary` (nền `bg-default` xám) trên cùng card (thầy soi devtools bắt: *"cái này áp rules phải là secondary chứ"*). Rule nền vẫn là [[elements/input]] §3 (field trên card/surface → secondary) — DatePicker chỉ khác CHỖ ĐẶT prop.
- Anatomy tối thiểu (theo docs HeroUI): `<DatePicker value onChange maxValue><Label/><DateField.Group fullWidth variant="secondary"><DateField.Input>{seg=><DateField.Segment segment={seg}/>}</DateField.Input><DateField.Suffix><DatePicker.Trigger><DatePicker.TriggerIndicator/></DatePicker.Trigger></DateField.Suffix></DateField.Group><DatePicker.Popover><Calendar>…header/grid/yearpicker…</Calendar></DatePicker.Popover></DatePicker>`. Precedent repo: `LivestreamCalendarModal` (đã dùng `@internationalized/date`).

## Luật 3 (STRICT) — ĐÍNH CHÍNH [[elements/alert]] §5: khi TOÀN BỘ Alert (không chỉ nút) LÀ funnel-CTA → chính Alert dùng `status="accent"` qua PROP, KHÔNG override className `bg-warning/10` tay
- Vòng trước (đã promote §5): "nút CTA trong alert tô theo status của alert" (nút accent trong alert warning). Thầy soi devtools thấy **card vẫn `alert--warning bg-warning/10`** (nền vàng) trong khi nút bên trong đã đổi accent → tông LỆCH (card vàng + nút hồng).
- **CHỐT LẠI:** khi NGUYÊN CÁI ALERT (không riêng nút) đóng vai funnel-CTA phổ quát (không phải "cảnh báo" thật) → set `status="accent"` (prop CÓ SẴN của HeroUI Alert, KHÔNG cần className hex/tint tay) + `className="bg-accent/10 shadow-none"` (nested-alert convention — [[elements/alert]] §3). Đừng chỉ đổi màu NÚT mà để nguyên `status="warning"` trên Alert — card + nút phải ĐỒNG TÔNG.
- Nguyên tắc rút ra: khi 1 Alert TOÀN THÂN là 1 CTA (không phải thông báo trạng thái/lỗi thật), set `status` = màu CTA đó luôn (accent), đừng chỉ vá nút bên trong.
