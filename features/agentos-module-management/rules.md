# Rules · AgentOS module management

- `BR-01` — UI may say Type; durable domain authority says `kind`.
- `BR-02` — Each module has exactly one kind from an extensible registry.
- `BR-03` — Kind is selected before draft creation and is immutable for that module.
- `BR-04` — Every module exposes shared chat.
- `BR-05` — Each kind resolves exactly one additional workbench contract.
- `BR-06` — Management separates common, chat and kind-owned settings.
- `BR-07` — Required common, chat and kind-owned settings must validate before readiness.
- `BR-08` — Failed readiness blocks activation with actionable missing-setting evidence.
- `BR-09` — Excel, Calendar, Document, Accounting and Scheduling are examples, not a closed enum.
